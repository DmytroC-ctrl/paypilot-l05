## Прогноз перед прогонами

Записано до прогонів набору `l05_dialogs.jsonl` (5 кейсів, `added_in: hw4`, `runs: 5`; `set_hash d33feb579bb0` на момент запису): прогони з 5 повтореннями почалися о 22:55 за +03:00, коміт прогнозу о 22:52. До коміту був виконаний один пробний прогін цього набору з `--repeat 1`; його звіт видалено, результат не переглядався. Стенд `lesson-05` (D06 + D07), `SUMMARIZE_AFTER_STEPS=2` (для CONV-004 кейс сам ставить 8), клієнт CUS-0004, час 2026-09-15T10:00:00+00:00.

**Крок втрати в усіх кейсах зі згорткою: 3** (згортка спрацьовує на першому кроці з номером більшим за поріг). Крок, на якому спрацює перша червона перевірка, залежить від проби.

| Кейс | Упаде на `lesson-05`? | Перша червона перевірка | Очікувана частка прогонів із 5 |
| --- | --- | --- | --- |
| CONV-002 (7 кроків, основний) | так | крок 5 (сума, reason code); крок 7 (дедлайн) | сума 4, код 5, дедлайн 5; кейс загалом 5 |
| CONV-003 (10 кроків, найгірший випадок) | так | крок 7 (дедлайн); крок 9 (код); крок 10 (сума) | дедлайн 5, код 5, сума 3 (найменш певна); кейс загалом 5 |
| CONV-004 (5 кроків, контроль, без згортки) | **ні** | немає | 0 червоних; ризик хибної червоної 1 з 5, бо проба вимагає, щоб відповідь назвала значення |
| MEM-001-AMT (4 кроки) | так | крок 4 (сума) | 5 |
| MEM-001-RC (4 кроки) | так | крок 4 (reason code, підміна на `service_not_rendered`) | 5 |

**На `clean`:** усі п'ять кейсів проходять. Найімовірніша хибна червона: CONV-003 на кроці 10 (два списання по 240 EUR, TX-0401 і TX-0402, агент може перепитати), приблизно 1 прогін із 5.

**Що спирається на дані, що ні.** Частки для CONV-002, MEM-001-AMT і MEM-001-RC взято з п'яти знятих прогонів кожного, тож це не сліпий прогноз. Частки для CONV-003 і CONV-004 спираються на один прогін 10-крокової версії (крок 8 дав цілий retrieval, сума в згортці вціліла) і один прогін 5 кроків із порогом 8 (згортки не було, значення збереглися). Для CONV-003 це найслабша частина прогнозу.

## Діалогові кейси

`set_hash`: **`d33feb579bb0`**, 5 кейсів. Кожен кейс має `turns`, `invariants` (з рівнем драбини), `min_turns`, `runs: 5`, `severity` і `added_in: hw4`.

| Кейс | Кроки · сутності · перемикання | Роль у плані | Severity · gate | Інваріанти (рівень драбини) |
| --- | --- | --- | --- | --- |
| CONV-002 | 7 · 4 · 3 | основний (сценарій C-07) | high · daily | сума (2), reason code (3), дедлайн (3) |
| CONV-003 | 10 · 4 · 5 | найгірший випадок | high · release | сума (2), reason code (3), дедлайн (3) |
| CONV-004 | 5 · 2 · 0 | контроль, без згортки | medium · daily | сума (2), reason code (3) |
| MEM-001-AMT | 4 · 1 · 2 | ізоляція осі (сума) | high · daily | сума (2) |
| MEM-001-RC | 4 · 1 · 2 | ізоляція осі (reason code) | critical · daily | reason code (3) |

Reason code перевіряється regex, тобто рівнем 3: loader курсу не приймає рівень 1 для тексту відповіді. Обґрунтування і оракули кожного інваріанта: розділ 4 плану.

## Прогони

Як відтворити (стенд `paypilot-stand` піднятий, у його `.env` `LLM_PROVIDER=anthropic`, ключ лежить лише там):

```bash
git clone https://github.com/alex-pancho/paypilot-l05-eval ~/paypilot/l05 && cd ~/paypilot/l05
cp <шлях до цього репозиторію>/l05_dialogs.jsonl sets/
bash api.sh PUT /api/_test/summarize_after '{"steps": 2}'
bash api.sh PUT /api/_test/clock '{"now":"2026-09-15T10:00:00+00:00"}'
docker compose run --rm eval --set l05_dialogs --dry-run          # set_hash d33feb579bb0
docker compose run --rm eval --set l05_dialogs --profile lesson-05
docker compose run --rm eval --set l05_dialogs --profile clean
```

Модель: `claude-haiku-4-5-20251001` (з `gen_ai.request.model` у трейсах; `LLM_MODEL` у `.env` стенду порожній). Час прогону `2026-09-15T10:00:00+00:00`, клієнт CUS-0004.

| Профіль | Звіт | Результат |
| --- | --- | --- |
| `lesson-05`, 5 прогонів на кейс | [reports/l05_dialogs-lesson-05-20261023T195505.json](reports/l05_dialogs-lesson-05-20261023T195505.json) | 1 з 5 кейсів пройшов (CONV-004, контроль) |
| `clean`, 5 прогонів на кейс | [reports/l05_dialogs-clean-20261023T201617.json](reports/l05_dialogs-clean-20261023T201617.json) | 5 з 5 кейсів пройшли, усі в 5 з 5 прогонів (25 з 25) |
